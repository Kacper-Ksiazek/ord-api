### TL;DR
Adds authenticated TTS streaming (`POST /api/v1/tts/speak`) and expands `openapi.json` with cookie-auth documentation, the existing QAW fill-gaps endpoint, and new TTS/QAW schemas. No breaking contract or auth-behavior changes for existing clients.

### Auth & security
- New protected path: `/api/v1/tts/**` added to `AUTHORIZED_PATHS` — TTS requires authenticated session.
- `POST /api/v1/quickly-added-words/ai/fill-gaps` remains authenticated (unchanged runtime behavior).
- Cookie `AUTH-TOKEN` (HttpOnly) — **unchanged**; OpenAPI `auth-cookie` security scheme and OTP-verify docs now describe cookie-based JWT more explicitly (no runtime auth flow change).

---

### Errors & edge cases
| Status | When | Frontend action |
|--------|------|-----------------|
| 400 | `POST /api/v1/tts/speak` — blank or >5000 char `text` | Validate `text` length client-side before calling TTS. |
| 401 | `POST /api/v1/tts/speak` — missing/invalid session | Ensure `withCredentials: true`; redirect to OTP flow. |
| 502 | `POST /api/v1/tts/speak` — ElevenLabs unavailable or not configured | Show fallback UI; retry or disable TTS playback. |
| 400 / 401 | `POST /api/v1/quickly-added-words/ai/fill-gaps` — invalid payload or unauthenticated | Use generated types; same handling as other authenticated QAW calls. |
